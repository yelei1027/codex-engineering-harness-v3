01

运行契约：一个 Main Router，其他能力都是被调用者

V3 只允许一个上层编排者。任何 Skill、Subagent、MCP 或 Hook 都不能在不受控情况下再建立第二套完整主流程。

1
唯一主编排者

Main Router

分类任务、控制权限、决定何时调用 Skill / MCP / Subagent、验收返回结果。

3
任务模式

L0 / L1 / L2

不按“文件多少”判断，而按风险、未知量、跨模块程度和交付门槛决定流程深度。

4
触发体系

Auto / 显式 / Tool / Hook

自然语言自动路由为默认；显式调用用于强制、调试和纠偏。

0
默认嵌套编排

禁止双重 Orchestrator

implement / implement-spec 不进入默认自动链；显式使用时 V3 外层实现编排暂停。

用户体验原则
用户平时只需描述“要做什么”。节点编号、任务包、child/run ID、证据 hash、失败返回点全部属于 Harness 内部日志，不应变成日常操作负担。
硬门禁
真实测试、实际 diff、权限审批、高风险独立审查、CI 与发布后验证不能因“流程精简”而被删除；可以合并重复检查，但不能取消它们承担的风险控制。
02

统一触发方式：自动为主，@ / $ / / 保留为显式入口

不同能力的触发机制不同。插件、Skill、MCP、Hook 与 Subagent 不使用同一个命令体系。

能力类型默认触发显式触发V3 规则
Plugin已安装且与任务相关时可被模型使用。@Codex Engineering Harness（ChatGPT 支持的界面）；Codex 可从插件来源/浏览器选择。@ 选择当前界面显示的已安装插件/Skill；不是执行某个 MCP 工具的通用命令。
Skill允许隐式调用且任务匹配时，Main 根据已加载的名称/描述选择。$harness-dev、$tdd、$code-review；Codex CLI/IDE 可用 /skills 选择。不依赖不存在或未验证的 /skill 单数命令；/skills 由 doctor 实测后再标记可用。

06

任务分级：先看风险，再看复杂度

Main 在任务入口分类，执行中若发现权限、迁移、数据损坏、并发等风险，可随时升级模式；不得从 L2 自动降级。

L0 · LIGHT

轻量修改

适用：文案、局部 UI、配置、低风险小 Bug、明确的一次性改动。

最小链：目标 → 改动 → 适用验证 → diff 检查 → 交付。

默认跳过：完整 PWF、正式 Spec、Ticket DAG、独立 Subagent、双重 Review。

L1 · STANDARD

普通功能 / Bug

适用：单模块到少量模块、有明确验收、风险可控的业务开发。

主链：Task Brief → TDD/实现 → 完整验证 → Review → PR/交付。

按需：researcher、CodeGraph、context-mode、PWF。

L2 · HIGH-RISK / COMPLEX

高风险或大型未知

适用：权限/认证、数据库迁移、资金/计费、并发、数据删除、跨服务契约、大型多 Ticket。

主链：正式 Spec → 风险/依赖 → TDD → 集成 → Spec/Standards Review → 独立风险 Review → CI → 人工发布。

强制：可追溯证据、独立第二视角、恢复方案。

风险覆盖复杂度
两行权限代码仍可能是 L2；500 行纯展示代码不一定是 L2。分类依据是“失败后果 + 不确定性 + 影响面”，不是 diff 行数。
