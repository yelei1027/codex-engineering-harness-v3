# v3.3.0 按需服务与资源管理

v3.3.0 按用户明确决定发布。原生 Desktop 审批与补丁工具证据仍不完整，保留为已知限制；发布不将这些项目改判为通过。

## 变化

- 完整准备后重型服务停止，由仅监听 loopback 的用户级 systemd 网关按实际调用启动。启动就绪共用 60 秒预算，最后活动请求结束后空闲 120 秒回收。
- MCP 发现不唤醒后端；项目共享同一部署，旧记忆库保留独立卷、原 URL、Scope 和 Revision。手动启动保持常驻意图，跨管理器重启保存。
- 活动调用持有租约；取消、会话删除及断开连接向后端传递取消。修正 SDK 先关闭会话而截断取消通知的竞态。取消不能撤销已提交操作，网络故障下仍是尽力语义。
- 截图前端使用生产静态构建；支持显式配置 Anthropic Messages 兼容模型，保留真实模型元数据、服务端凭据和 token/轮数限制。
- `harness resources status` 查看资源；测试 GC 只收集已登记、归属可验证且无使用者的部署，保留数据卷、源码及报告。
- 内部固定全量测试预算为 600 秒；外部自定义检查最多 120 秒。超时终止专属进程组。

## 当前 3.3.0 包验证

- 版本整理后全量 281 项测试通过（133.630 秒）；真实 `install --prepare` 完成。
- 47 工具发现不唤醒，冷调用 2.468 秒，空闲 121.974 秒回收；手动常驻跨重启和 125 秒保持。管理器观测峰值 17,272,832 字节。
- 前端 25 次请求峰值 34,852,864 字节，比 600 MiB 基线降低 94.46%。
- 两个真实隔离项目共享部署，Scope 不同；重启后精确记忆及 Revision 回读一致，跨 Scope 请求拒绝。
- 实际 PowerContext 数据库锁竞争下，取消、删除会话和断开连接均观察到后端取消计数，未提交测试 Scope。
- 包内文件完整性、版本一致性与隐私扫描通过。测试部署通过登记回收，保留卷、源码及报告。

## 已知限制

- 原生 Codex Desktop 审批/工具调用。当前环境不能控制原生界面，CLI/SDK 结果不能替代；既有未验证边界保留。
- 第三方 Provider 实际多轮工具执行。本次基本生成成功不代表 Replicate 图像生成、Gemini 资产提取等附加能力可用。

## 安装与维护

命令在 Linux x86_64 系统终端的 Bash 中执行；自然语言任务在 Codex Desktop 项目聊天框中发送。支持范围不扩展到未验收的 Windows/WSL。完整准备需要网络和可用 Docker、用户级 systemd；发行包不是离线镜像集合。

旧项目不会因新版本准备或接受自动迁移；活动项目保留原绑定。不要覆盖旧安装或手工改写记忆来源。首次接入、候选更新、显式项目迁移及卸载恢复分别按 [安装说明](../INSTALLATION.md) 执行。
