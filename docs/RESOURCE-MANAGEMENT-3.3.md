# v3.3 按需服务与资源管理

本页描述 v3.3.0 实现契约。已完成的集成验证与原生 Desktop 未验证边界见 [发行说明](RELEASE-3.3.0.md)；正式发布不代表原生审批和补丁工具验收通过。

完整准备安装会构建受管镜像、采集真实 MCP 发现元数据，再停止重型容器并注册用户级 systemd 网关。网关只监听 loopback；准备完成后处于按需模式。首次实际调用启动对应后端，启动及就绪共用 60 秒预算；最后一个活动调用结束后空闲 120 秒回收。失败启动进入可见失败状态，回收器重试清理已启动资源。手动 start 保持常驻意图，跨管理器重启保存；stop 清除常驻，保留数据。活动调用期间拒绝停止和维护。

`harness resources status` 读取状态、活动调用、空闲剩余时间、容器及管理器内存；发现和状态读取不唤醒后端。多个项目绑定同一部署时共享资源租约，不因项目数复制容器。旧库保持独立卷、原 URL 和 Scope/Revision，后端端口与公共网关端口分开。动态删除仅在无活动调用时关闭监听；恢复前检查原端口未被占用。

每个 HTTP 监听器最多 16 个接入连接、8 个后端工作请求。执行容量满时拒绝额外工作，保留接入余量供状态、发现、会话删除和取消通知。连接读取有超时；该余量不是对恶意慢连接的无限容量保证。MCP 未 DELETE 的空闲会话 30 分钟过期，最多 128 个；活动调用的会话不因空闲超时被清除。过期返回 404，客户端需重新初始化。取消按会话和请求 ID 隔离。SDK 取消通知发送完成后才删除和关闭后端会话，避免关闭截断通知。取消采用尽力语义：网络故障或超时不能保证已提交操作撤销；实际后端停止效果需单独验收。

截图前端使用生产静态构建和 Node HTTP/WebSocket 代理；WebSocket 增量解析首个应用帧，纯控制帧不会永久保持租约。没有真实 Provider 生成证据时不得报告生成验收通过。

候选更新的强制内部 unittest 全量检查预算为 600 秒。外部自定义检查仍最多 120 秒，包括标为 STATIC 的外部检查。内部预算只用于固定全量命令；超时或中断会终止专属进程组。结构检查、单元测试、真实 Docker/SDK 和原生 Desktop 是不同证据，不可互相替代。

测试 GC 仅处理显式登记、所有者已结束、归属未改变且没有消费者或项目绑定的测试部署。默认预览，apply 再核验后回收容器、网络和受管网关；保留卷、源码、日志及报告。未登记环境不按名称或目录年龄猜测回收。


## 第三方兼容模型配置

截图后端可通过 `HARNESS_SCREENSHOT_MODEL` 显式启用 Anthropic Messages 兼容适配。配置仅放在受管部署的 `runtimes/screenshot-to-code/.env`，权限 0600；不放入源码、报告或 Git。需要同时提供 `ANTHROPIC_API_KEY`、HTTPS `ANTHROPIC_BASE_URL` 和真实模型 ID。未设置模型变量时沿用上游原生 Provider。页面与日志使用真实模型 ID，不把 DeepSeek 标为 GPT。

该模式复用锁定上游 Agent、工具与官方 Anthropic SDK；适配模块由 Harness 管理，在独立构建目录加入镜像，vendor 保持不变。沿用上游流式解析及工具图片回传，保留截图预览和工具调用能力。地址末尾的 `/v1` 会规范化，避免 SDK 重复拼接 `/v1/messages`。截断、取消或不完整响应不能作为成功。SDK 不自动重试，重定向被禁止，WebSocket 请求不能改写管理员指定的地址或密钥。图像生成/编辑仍需单独的 Replicate 配置，资产提取需 Gemini；仅提供 DeepSeek 密钥不代表这些附加服务可用。

兼容模式默认生成 1 个候选，每轮最多 8192 输出 token、最多 8 轮；可用 `HARNESS_SCREENSHOT_VARIANTS`（1–4）、`HARNESS_SCREENSHOT_MAX_TOKENS`（256–32768）、`HARNESS_SCREENSHOT_MAX_TURNS`（1–30）显式调整。中转站价格未知时不虚报美元费用，仍执行 token 和轮数限制。模型与中转站的图片、流式工具调用能力必须实测。
