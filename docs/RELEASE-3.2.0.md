# 3.2.0 发行说明与已知限制

v3.2.0 按用户明确决定作为下一正式发行版提供下载。完整 PRD 的 60 项需求与 22 个场景继续保留；正式发布不代表尚缺证据的验收项已通过。

文档已补充执行位置说明。Release 的独立 Markdown/HTML 附件与在线指南为更新后的说明；原 v3.2.0 程序安装包及其 SHA256 保持不变，包内文档可能早于本次说明修订。

## 下载后在哪里操作

| 操作 | 位置 |
| --- | --- |
| 下载、安装、`harness` 命令 | 安装所在 Linux 电脑的系统终端，使用 Bash；不要粘贴进 PowerShell/CMD |
| “用 Harness……”等任务需求 | Codex Desktop 打开业务项目后的聊天输入框 |
| 项目加载、只读/写权限、Hook 信任 | Codex Desktop 原生界面与权限菜单 |
| 阅读 HTML 手册 | 下载 HTML，在浏览器打开；浏览器不执行安装命令 |

本版目标为 Linux x86_64；Windows/WSL 未完成独立安装验收。首次安装、首次接入、日常聊天和旧版升级是四个不同步骤，按上方分步指南依次选择。已有旧版请使用更新流程，不重跑首次安装覆盖它。

## 主要变化

- 明确选择 Harness 后，模糊需求先检查、提供建议并确认具体范围；项目准备与业务修改分别授权。
- 安装预检区分缺失依赖和访问被拒；准备失败报告实际阶段，同目录重试保留受管进度与数据。
- 服务构建复用核对源码、依赖、镜像、部署身份、端口和挂载；部分启动失败可接续，冲突保留现场。
- 候选准备、版本接受与已有项目迁移分开；卸载、重装与记忆恢复保留用户数据，并核对所有权。
- 同步技能行为清单、安装说明及两份 HTML 手册。

## 已执行的验证

- 当前行为源码全量回归：226 项通过；最终源码独立审查未发现未解决的确定缺陷。
- 隔离安装：一次受控服务启动失败后，同目录重试成功；实际依赖和 Docker 服务参与运行。
- 实际组件调用：context-mode 3 次、CodeGraph 1 次、MarkItDown 1 次通过；服务验证通过。
- 隔离安装卸载、原目录重装与原记忆 Scope/Revision 回读通过；业务文件、任务记录、无关配置及诊断日志保留。
- 公共 CLI 候选提升及跨根项目迁移通过，迁移后的原记忆回读通过。

安装包验收中的未发布 GitHub 下载和登录检查使用本地传输夹具，因此不证明正式 Release 下载或新机器登录已验证。故障注入仅证明对应恢复场景。原生交互证据部分来自相关源码未变的历史测试，不能推导所有桌面分支通过。

## 尚未完成的验收

- 原生补丁工具拒写的原始返回无法通过当前桌面卡片或读取接口取得。已有只读状态、文件未变及助手转述，但不能替代原始工具证据；该项保持未验证，未判定为成功或产品失败。
- 完整 60 项需求／22 个场景的最终逐项验收尚未签署。源码审查通过不等于完整产品验收通过。
- 候选提升的 `doctor` 总体结果为 `UNVERIFIED`；八类限定验收记录通过，不代表所有原生能力均已验证。
- 增强生成 Provider 缺少额外配置的能力保持待配置；服务存活和渲染测试不代表生成能力通过。

## 与原 V3.0.0 HTML 的差异

工程主线仍是 Main 路由、风险分级、需求与规格、实现与测试、冻结审查、交付、恢复和维护。旧文档的编号节点仍保留；新版手册按使用旅程呈现，并保留工程节点附录。节点存在是契约兼容证据，不等于每个分支都完成原生验收。

| 项目 | 原 HTML | v3.2.0 |
| --- | --- | --- |
| 启动 | 自动匹配为主，显式调用纠偏 | 本聊天明确选择 Harness 后才进入流程 |
| 模糊需求 | Main 自动路由 | 先只读检查、给建议，确认关键取舍和范围 |
| 确认次数 | 按节点与审批分支说明 | 同一适用范围不重复确认；扩大范围再确认 |
| 项目接入 | 安装、启用与技能入口说明 | `start` 先预览，`prepare --apply` 执行已确认准备 |
| 权限 | 设计要求真实沙盒门禁 | `harness-inspect` 与实际宿主状态核验；批准后切写、交付后恢复只读 |
| L2 | 高风险/复杂任务模式 | 保留任务风险分级，另区分默认 L2 接入配置（Hooks） |
| 更新 | 隔离候选与验收原则 | 公开 CLI 候选接受、跨根迁移及数据恢复路径 |
| Handoff | 跨会话正式交接 | 同任务先本地 Checkpoint，确需跨会话再正式 Handoff |

日常仍然使用自然语言，不要求逐节点手工操作。首次接入和原生 Hook 信任仍需完成；日常无需反复输入 @ 或 $。权限菜单能力与当前有效权限要分别核对。
